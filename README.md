# 地区 × 品类 预测校准计划表

把**地区**和**品类**两套互相独立、彼此对不上的预测，合并成一张能对上账的计划表。

每个「地区 × 品类」单元格是底层单元；地区总量、品类总量、全盘总量都由底层求和得到。
每一层都可以有各自的原始预测与可信权重，**不要求它们事先相等**。校准就是在满足锁定值
的前提下，为所有已提供的预测找到加权平方偏差最小的一张表。

纯 Python 标准库 + 原生前端，**零第三方依赖**，Python 3.8+ 即可运行。

## 快速开始

```bash
python3 run.py --port 8000
# 打开 http://127.0.0.1:8000
```

页面默认载入「地区与品类预测明显对不上」的示例。页签流程：

1. **编辑草稿** —— 填/改预测、权重、锁定值；载入示例、导入 JSON/CSV、增删地区与品类
2. **校准前后对比** —— 每个单元格与总量的校准值、与原始预测的差值、被压到 0 的标记
3. **目标函数与校验** —— 逐项列出 `w·偏差²` 并求和核对，锁定残差、非负性、迭代信息
4. **发布记录** —— 不可变快照列表，可查看任意一次发布的完整输入与结果

## 校准模型

变量：`x[r][c] ≥ 0`（每个地区 × 品类单元格）。

- 地区总量 `R_r = Σ_c x[r][c]`，品类总量 `C_c = Σ_r x[r][c]`，全盘 `G = Σ x[r][c]` —— 全部由底层求和；
- 目标函数 `F(x) = Σ_{已提供的预测 k} w_k · (agg_k(x) − f_k)²`；
- **未提供的预测不进入目标函数**（不会被当成 0）；提供了预测值的项，权重必须为正；
- 锁定值（地区总量 / 品类总量 / 全盘总量均可锁定）是等式约束；
- 求解是**两阶段字典序**：
  1. 最小化 `F(x)`；
  2. 在所有最优解中取 `Σx²` 最小者 —— 同样的输入永远得到同样的计划。
- 缺底层预测的单元格不由目标函数直接约束，但仍被总量预测与锁定值间接决定。

## 冲突与不可行

锁定的地区总量之和与锁定的品类总量之和必须相等（它们都等于全盘总量），负的锁定值
则直接与非负约束冲突。不可行时：

- 后端用**删除过滤法**在单纯形可行性预言机上求出一个**不可约不可行子系统（IIS）**，
  页面会列出参与冲突的每一条锁定；
- 每条锁定旁有「撤销此锁定并重算」按钮，撤销任意一条 IIS 成员后重算即可恢复可行；
- **没有可行方案时不能发布**（前端禁用 + 后端 409 双重把关）。

## 求解器与结果校验

环境无法联网安装成熟求解器（cvxpy/scipy），因此内置了一个纯 Python 求解器，
但**校验标准不打折**——绝不「只看它返回了数组」：

- **积极集法**解凸 QP：每轮迭代解等式约束 KKT 系统（奇异但相容的系统用全主元高斯
  消元处理），返回前显式检查 KKT 残差（驻点残差、等式残差、乘子非负）；
- **Phase-I 单纯形**（Bland 法则，保证终止）做可行性判定与 IIS 计算；
- 第一阶段最优面是多面体 `{x ≥ 0 : Aeq x = b, Hx = Hx₁}`（梯度条件因
  `c ∈ row(H) ⊥ null(H)` 而自动成立），用预测项矩阵的行基等价表示后，第二阶段在
  该面上最小化 `Σx²`；项矩阵行满秩时最优解唯一，直接跳过第二阶段；
- 每次校准后重新按定义核算：每个汇总值由单元格重新求和、目标函数逐项重算、
  锁定残差与最小单元格值检查，任何一项不合格都返回 `solver_error` 而不是坏数字。

测试覆盖：解析解对照（水位填充、均分、零单元格算例）、随机可行扰动下目标值不减、
缺失预测不参与目标、权重效果、IIS 成员删除任一即可行、发布不可变等。见 `tests/`。

## 发布

- 发布时**服务器用冻结的输入重新求解**并整体存档：预测、权重、锁定条件、结果、
  时间戳与内容哈希（SHA-256）；
- 发布记录**不可变**：没有更新/删除接口，改草稿不会悄悄改变已发布计划；
- 存储为 SQLite（默认 `data/planner.db`，可用 `--db` 指定）。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/calibrate` | 校准。返回 `optimal`（计划+逐项目标+校验）或 `infeasible`（IIS 冲突列表） |
| POST | `/api/publish` | `{name, input}`，服务器重解并存档；不可行返回 409 |
| GET | `/api/published` | 发布记录列表 |
| GET | `/api/published/<id>` | 单条发布快照（完整输入+结果） |
| GET | `/samples/<name>.json` | 示例数据 |

### 输入 JSON 结构

```json
{
  "regions": ["华北", "华东"],
  "categories": ["饮料", "零食"],
  "cells":         {"forecast": [[100, 120], [90, null]], "weight": [[1, 1], [1, null]]},
  "regionTotals":  {"forecast": [300, 260], "weight": [3, 3], "lock": [300, null]},
  "categoryTotals":{"forecast": [260, 220], "weight": [2, 2], "lock": [null, null]},
  "grandTotal":    {"forecast": 800, "weight": 1, "lock": null}
}
```

`null` = 不提供（预测/权重）或不锁定。CSV 导入格式：`地区,品类,预测[,权重]`（含表头，
见 `samples/cells_example.csv`），只填充单元格，总量在页面中继续编辑。

## 示例数据（`samples/`）

| 文件 | 演示 |
|---|---|
| `mismatch.json` | 单元格合计 1080、地区合计 1140、品类合计 1120、全盘 1150，四套预测明显对不上 |
| `missing_base.json` | 三个单元格缺预测，由地区锁定与品类预测间接决定 |
| `lock_conflict.json` | 地区锁定合计 600 vs 品类锁定合计 800，IIS 列出全部 4 条冲突锁定 |
| `zero_cell.json` | 品类锁定 0 把整列压到零；其余单元格有解析解可对照（100/100/150/150） |

## 目录结构

```
run.py                 启动入口
planner/
  linalg.py            稠密线性代数（全主元消元，相容奇异系统）
  qp.py                积极集 QP + Phase-I 单纯形（含 KKT 残差校验）
  calibrate.py         校验、建模、两阶段字典序求解、IIS、结果核算
  storage.py           SQLite 发布记录（不可变）
  server.py            HTTP 服务（API + 静态文件）
static/                前端（原生 HTML/JS/CSS，无构建步骤）
samples/               示例数据（4 个 JSON + 1 个 CSV）
tests/                 后端单元测试 + 前端冒烟测试
```

## 限制

- 纯 Python 求解器面向中小规模：≤10×10 约 1 秒，15×15 约 13 秒；网格上限 256 个
  单元格（`MAX_CELLS`），更大规模建议接入 cvxpy/OSQP 替换 `planner/qp.py`（接口已隔离）。
- 数值容差：锁定残差 ≤ 1e-6（按总量缩放），非负性 ≥ -1e-7。
